# 档案契约与证据边界

Python 3.10+，运行时仅使用标准库。核心证据脚本不联网、不下载档案、不刷新数据、不调用模型；可选套餐执行器另见 chatgpt-plan.md。档案持有者自行提供有权使用的本地数据。

## 支持的输入

```text
PROFILES_DIR/
  archives_v2027/USER_ID.json
  archives_extended/USER_ID.json
```

按 ID 先读核心档，未找到才查扩展档；找到损坏或 ID 不一致的核心档时报告错误，不悄悄换用其他用户。ID 只允许字母、数字、下划线、连字符，最长 80 字符。单份 JSON 上限 8 MiB。支持的原始字段：

```json
{
  "buyer_id": "demo-rich",
  "L1_facts": {},
  "L2_attitude": {
    "nps_history": [
      {"date": "2025-01-01", "industry": "domestic_hotel", "score": 8, "tags": ["示例标签"]}
    ],
    "verbatims": [
      {"date": "2025-01-01", "industry": "domestic_hotel", "score": 8, "text": "合成示例原话"}
    ]
  }
}
```

原档案若将 `nps_history` 放在 L1，脚本会在 L2 不含该字段时回退到 L1。支持 STRING 或整数用户 ID。`verbatims` 必须是带日期的对象列表，不读取没有时间来源的纯文本列表。`score` 支持 0—10 的整数或可解析为整数的数值字符串；0 保留，布尔值、越界和非整数视为未知分数。记录有有效标签或原话时，即使分数未知仍可作为该字段的证据。

同一参评的分数标签与原话通常分列于两个数组，保留为不同证据，不凭相同日期擅自合并，避免把他条反馈附到错误事件上。完全相同的规范化记录去重。摘要的参评条数和均分只计算选中的 survey 记录，不把原话再当一次参评。

alpha.10在证据包内增加`source_map`（record-fields-v1）：按同一E记录列出kind、日期、行业、原来源字段、记录哈希及F编号映射；不复制字段值，不关联不同记录为同一事件。与目录一样，只从所选可见记录计算，包哈希和验证器核对映射一致；新包缺失或篡改映射会拒绝，旧alpha.1–alpha.9包无此字段仍可读取。访谈目录的source-map.json只是查看副本，以evidence.json内映射为准。关联不能代替模型显式选取所需字段，也不验证原始自述真实或推断成立。

支持行业：`airplane` 国内机票、`domestic_hotel` 国内酒店、`intl_flight` 国际机票、`intl_hotel` 境外酒店、`intl_vacation` 国际度假、`rental` 租车、`train` 火车票、`vacation_route` 国内度假线路、`vacation_ticket` 国内度假门票。未知行业枚举和日期不可解析的记录不进入模型输入。

## 时间与检索

`--cutoff` 为严格排他边界，记录时间必须早于它。无时区的日期或时间按 `Asia/Shanghai` 的固定 UTC+08:00 解释；带偏移的时间先换算。日期 `2026-01-01` 表示 1 月 1 日零点，不包括这一天。无 cutoff 时提供该静态档案全部可用历史，不表示实时数据。

先按时间与行业过滤，再以问题英文词和中文二字片段的重合度排序，同分时优先较新记录；默认最多 24 条、规范化证据内容约 40,000 字符。可以调整 `--max-records`（1—100）与 `--max-chars`（500—200000）。这是确定性关键词检索，不是向量检索。超出字符预算的整条记录被跳过，不把截断原话伪装成完整引文。选定记录最终按时间排列。

只对选中的记录重新计算均分、首末分数、行业条数与证据深度。记录来源字段和规范化记录 SHA256 用于本地追溯；证据包包含自身校验和。不得把 SHA256 当真实性认证，它只能帮助检测意外内容变化。

## 始终排除的内容

- 真实 ID、昵称和无历史时点的人口画像不进入证据包；使用由 ID 派生的化名。
- 现有全历史 `trajectory`、`tag_frequency`、`nps_meta` 等汇总不复用。
- L3 性格、L4 因果叙事及独立 `enhanced` 输出不进入首版输入。
- 不输出隐藏记录的条数、摘要或全档案摘要，避免从侧面透露未来信息。

化名不是匿名化保证。原话可能包含姓名、订单、手机号等，任何外部分享仍需根据实际内容脱敏。

## 能力降级

证据深度仅由选定证据计算：没有证据为 `insufficient`；有记录无实质原话为 `facts_only`；有原话但深度不足为 `limited_attitude`；至少 3 条 survey、3 条实质原话且时间跨度至少 180 天为 `individual_memory`。这个阈值是工程启发式，尚未验证可信度，也不等于历史实验计划中的严格候选规则。

alpha.2 会校验证据条目的字段、分数类型与范围、来源记录校验值、排序和摘要一致性，异常输入返回 JSON 错误；不接受非有限 JSON 常量与重复键。

`check-answer` 要求 alpha.2 回答携带当前证据包的 `bundle_sha256`，不允许把另一问题或用户的回答直接挪用；正文引用与结构化 claims 必须相互覆盖。仍兼容读取 alpha.1 的合法包，但未绑定的旧回答会有显式警告。

以上检查仍不能证明语义正确。引用存在不等于引用支持结论；回答文本是否编造、是否遗漏关键条件、是否错误归因，需要宿主 AI 或人工复核。

alpha.5 不用空栏目或乱码升级证据深度；原始行仍保留，不伪装成被核实的有效意见。旧包沿用它生成时的分类口径，不重写历史包。新回答优先 typed-source-v2：facts 只定位原字段，inferences 显式推断；程序统一渲染引用。字段忠实不等于自述真实、推断正确或理论成立，见[推演方法](evidence-reasoning.md)。
