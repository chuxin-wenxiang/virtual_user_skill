# alpha.11：保留问题证据与最近背景，减少试验消耗

2026-10-31。本文记录alpha.11的检索、批试契约与执行前修订。发布时176项离线检查通过，现有套餐授权及无资料探针成功，新8人已冻结、等待当批确认，尚无该批效果结果。随后用户明确同意，本批已按alpha.11冻结算法完成64次生成、16批来源审核；完整结果、分歧和预测限制见[alpha.12补充报告](pilot-20261031-context.md)。历史发布标签保留当时状态，不覆盖。

## 检索变化

默认`question_recent_context_v1`先选预算内最相关记录作为问题锚点，补入锚点行业最近调查时点的全部survey记录，并尽量保留一条最近原话，然后按原关键词排序填余量。日期、行业过滤仍在检索前执行；不切碎超预算原文，不跨记录拼造同一事件。

同一调查时点有不同评分时，全部作为独立E记录保留；若整组放不进预算，跳过该组并记录`budget_excluded`，不挑其中一个冒充唯一最近评价。新证据包的first_score/latest_score在所选首末时点存在不同分数时为null，均分和条数仍按所选survey记录计算，不把原话重复算参评。旧版本摘要语义保持原样，用于历史复现。

该策略可能用最近背景替换较低排序的主题记录，不保证语义检索或预测更好；只为锚点行业保留背景，不代表完整历史。`selection.context_audit`给出所选记录数、字符预算和最近背景状态；验证器核对能从所选记录重算的计数与引用，不认证完整档案或自然语言支持。显式选择旧策略：

```bash
python3 scripts/authentic_user.py prepare --profiles-dir examples/profiles --buyer-id demo-rich --question '酒店体验' --cutoff 2026-01-01 --selection-policy question_token_overlap_then_recency --output /private/tmp/keyword-memory.json
```

source_map继续帮助选择同一记录的score/text/tags，判断仍须显式引用全部前提。原话与评分不一致时保留不一致；零分不自动支持退订、费用等具体主题。来源审核仍只看该判断实际选中的完整字段与日期。

## 批试契约补齐

新单记忆臂输入携带从所选证据计算的capability，输入审计重算核对，生成渲染、导入、原始失败评分和预检均遵守该档位。facts_only不能产生推断，insufficient必须未知，limited_attitude只能有界表达；档位不是可靠性认证。冻结为atomic的回答不能混入旧自由文本并算有效，原始失败仍完整保留。

准备中发现批试缺少档位、摘要可能任意选并列评分，均在任何新用户模型请求前修正；原计划、源码及材料副本保留，用户、问题、证据和隐藏参考未变。两处合成示例/测试夹具的哈希绑定问题也保留开发记录后修正；这些是工程回归，不是独立效果验证。

## 单记忆臂与脚本基线

原有标签—记忆双臂流程保留。新增`memory_vs_computed_baselines`：四题、两次重复、每人仅一个M记忆臂；8人共32份提示词、64次生成，最多16批来源审核。Q2的最近同业NPS延续和固定推荐/观望/不推荐由本地脚本计算，没有额外模型标签臂。

```bash
python3 scripts/validation_prep.py build --profiles-dir /absolute/path/my-profiles --input-dir /private/tmp/memory-inputs --judge-dir /private/tmp/memory-judge --comparison memory_vs_computed_baselines --response-protocol atomic-bound-v4 --include-zero --max-records 24
```

以上CLI保留原分组选样入口；真正的未见用户验证仍须显式排除所有旧人并设`fresh_holdout=True`，不能直接把默认分组样本称独立。冻结、导入、完整网格审计、盲评包及评分汇总支持新M臂；语义指标按用户作描述性汇总，Q2另作脚本基线配对。不是64个独立人，也不自动得出有效结论。新检索参与准备时，套餐配置须将record_selection.py加入冻结执行源。
